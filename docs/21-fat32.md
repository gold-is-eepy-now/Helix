# 21. FAT32: stage 1, read-only

Status: **read-only, whole-device volumes; tested on the host and under QEMU (TCG). Not run on
real hardware.** Written from Microsoft's "FAT: General Overview of On-Disk Format"; no other
kernel's source was used.

## What it does

- `fat32_mount(dev, first_lba)` reads the boot sector, validates it (sector size, cluster size,
  FAT count, signature, FAT32 layout) and decides the FAT type the way the specification says:
  by the number of data clusters. FAT12 and FAT16 are refused, with a reason in
  `fat32_mount_error()`.
- Cluster chains use 28-bit FAT entries (end of chain at >= 0x0FFFFFF8, bad cluster 0x0FFFFFF7).
  Chain loops, out-of-range clusters and chains shorter than the file size are detected and fail the read.
- Directories: 32-byte entries, deleted entries skipped, the volume-label entry skipped, `.` and `..` listed.
  Long names (VFAT) are assembled with sequence and checksum validation and converted from UTF-16 to UTF-8
  (surrogate pairs included). Short names honour the NT lowercase flags.
- Paths use `/`; `.` and `..` are resolved; lookup ignores case for ASCII letters only.
- The volume label comes from the root directory entry, else the boot sector.
- Block devices with sectors larger than 512 bytes are handled by a ratio; AHCI disks are 512.

## Shell

`fat <dev> info | ls [path] | cat <path> | sum <path>`, for example `fat sata1 ls /DOCS`.
`ls` prints `d` or `f`, the size and the name. `sum` reads the whole file and prints its length and byte sum.

## Not done

- Writes of any kind (create, append, delete, FAT updates, FSInfo).
- MBR/GPT partition parsing: the volume must start at the LBA you pass (0 from the shell).
- Mounting into the file tree (the ext4 root is still the only mounted filesystem).
- Case folding beyond ASCII, 8.3 name generation, exFAT.

## Tests

- `tests/fat32-test.sh` (part of `make test`): builds two images with `mkfs.fat` (512-byte and 4 KiB clusters)
  and `mtools`, then runs `tests/fat32-test.c` against the real driver source: listing, case-insensitive
  lookup, `.`/`..`, long and accented names, a surrogate-pair name, whole-file and ranged reads at cluster
  edges, a file whose chain was rearranged out of order by editing the image, a chain cut short, and refusal
  of FAT16 and blank volumes. It prints SKIP and exits 0 if `mkfs.fat` or `mtools` is missing.
  mtools cannot write characters outside the Basic Multilingual Plane, so the surrogate-pair entry is patched
  into the image by the script.
- `tests/shell-test.py` builds a FAT32 image at run time, attaches it as the second IDE disk (`sata1`) and checks
  `fat sata0 info` (refused), `fat sata1 info`, `ls`, `cat`, and a 100000-byte `sum` against the host's sum.
  The checks are skipped with a printed note if the tools are missing.
