# 27. 32-bit (i686) port: plan

Status: **I0 done (QEMU only).** Helix's x86_64 kernel is unchanged; the i686 kernel is a
separate build in `kernel-i686/`. Helix runs on x86_64 only, in the main kernel. Nothing in this
document is built or booted. Each milestone below is done only when it has been built
and booted (QEMU is fine for the first milestones) and its success line is checked.

## Why this is a port, not a flag

A 32-bit (IA-32) CPU cannot run the x86_64 kernel. The kernel uses long-mode boot, 4-level
page tables, 64-bit assembly and interrupt frames, the 64-bit ELF loader and the 64-bit
syscall path. So an i686 build is a second kernel that shares the portable C code.

## What was measured (2026-11-23)

- 94 kernel C files, 5 assembly files (`kernel/src/*.S`).
- 11 files contain x86_64-specific code (`%r*` registers, `iretq`, `cr3`, MSRs).
- 1 file depends on 64-bit ELF (`Elf64_`).
- Build flags are fixed to `-m64 -march=x86-64 -mcmodel=kernel` (kernel) and
  `-m64 -march=x86-64 -mcmodel=small` (user programs).
- **Limine cannot boot an i686 kernel.** Tested with Limine 12.9.6: its BIOS loader and its
  IA-32 UEFI loader (`BOOTIA32.EFI`, run under OVMF32) both stop with
  `elf: Not an x86-64 ELF file`. Limine loads only x86-64 kernels, whatever firmware it runs
  on. So the i686 boot protocol is **Multiboot 1**, loaded by GRUB (BIOS) or by QEMU's
  `-kernel`. This replaces the Limine plan in the first draft of this document.

## Milestones

| Milestone | Goal | Gate (must be seen) |
| --- | --- | --- |
| **I0** | i686 build (`kernel-i686/`): `-m32`, a Multiboot 1 ELF32 kernel linked at 1 MiB; GRUB boots it from a BIOS ISO. The kernel checks the Multiboot magic, prints over COM1 and halts. | **Done:** `make i686-bios-test` prints `HELIX OS i686` and `Boot successful.` under SeaBIOS (`qemu-system-i386`). Also checked: `qemu-system-i386 -kernel` and `grub-file --is-x86-multiboot`. Not yet tested on real BIOS hardware. |
| **I1** | Architecture split: move the x86_64 pieces behind `kernel/arch/x86_64/` and add the `kernel/arch/i686/` slot. The x86_64 build must not change. | **Partly done:** `kernel/arch/x86_64/` holds the 5 assembly files, `gdt.c`, `kernel_stack.c`, `apic.c` and `nx.c` (the EFER write split out of `cpu.c` as `arch_enable_nxe()`). `make test`, `make iso`, `make bios-test` and `make i686-bios-test` pass. Also moved: `vmm.c` (page tables), `idt.c` (interrupt table) and `usermode.c` (ring-3 entry; it also holds the ELF64 loader, to split in I4). The interfaces (`vmm.h`, `gdt.h`, `thread.h`, `io.h`) stay in `src/` for now; `syscall.c` is generic dispatch. No i686 arch files yet. |
| **I2** | i686 paging and memory: 32-bit page tables (PAE first, for NX and >4 GiB), PMM and heap on i686. | **I2a done (QEMU only):** the frame allocator (`kernel/src/pmm.c`) now takes a neutral region list (`struct pmm_region`). x86_64 translates Limine's map into it in `main.c`; i686 translates Multiboot's map in `kernel-i686/main.c`, clips out the kernel image and anything above 4 GiB, and runs `mm_test.c`. `make i686-bios-test` prints `HELIX i686 mm: PASS`. **I2b done (QEMU only):** i686 paging is PAE (`kernel-i686/paging.c`, `paging.h`): a PDPT of four entries, PD and PT tables in static arrays, identity map of RAM with 2 MiB pages, CR4.PAE set before CR0.PG. `paging_map4k`/`paging_unmap4k` split a 2 MiB page on demand; `vm_test.c` maps 1 GiB, writes through it, reads it back through the identity address and unmaps it. The shared `kernel/src/heap.c` now builds for i686 (`heap_init(0)`) and `heap_selftest` runs. The boot test expects `HELIX i686 paging: PASS` and `HELIX i686 heap: PASS`. NX (EFER.NXE) is not enabled on i686 yet. |
| **I3** | i686 core: console, keyboard, PIT timer, scheduler and context switch, serial shell (`helixsh`). | Serial shell runs `sysinfo` and `ls` under QEMU |
| **I4** | ELF32 loader and ring-3 programs with `int 0x80` syscalls using the 32-bit ABI. | A 32-bit user program prints via a syscall and exits |
| **I5** | Storage and filesystems (ext4 read, FAT32) and PCI on i686. | `disk` and `fat` checks pass on i686 |
| **I6** | Decide, per subsystem, what is in or out for i686: networking, desktop, TLS, Mac and DoneJS compatibility, Linux compat. | Written list in this file |

## Out of scope for the first pass

- The Mac/Darwin compatibility layer and DoneJS (both 64-bit today).
- The 64-bit TLS suites (`x25519`, `chacha20`, `x509`) unless they build cleanly on i686.
- Real hardware. Every i686 claim starts as a QEMU result.

## Open decisions

- Boot on real 32-bit UEFI machines would need GRUB's IA-32 EFI loader (not built yet); the
  I0 path is BIOS only.
- PAE or non-PAE paging for i686. PAE is needed for NX and memory above 4 GiB, and is the
  default assumed here.
- Whether the i686 build keeps the same syscall numbers as x86_64.
- Whether i686 gets its own `version.h` identity string (`i686` suffix).

## Honesty rule for this port

The i686 kernel is not called working until each milestone above has been built and its
gate seen in a run. Until I0 passes, the answer to "does Helix support 32-bit?" is no.
