# 27. 32-bit (i686) port: plan

Status: **planned, not started.** Helix runs only on x86_64 today. Nothing in this
document is built or booted. Each milestone below is done only when it has been built
and booted (QEMU is fine for the first milestones) and its success line is checked.

## Why this is a port, not a flag

A 32-bit (IA-32) CPU cannot run the x86_64 kernel. The kernel uses long-mode boot, 4-level
page tables, 64-bit assembly and interrupt frames, the 64-bit ELF loader and the 64-bit
syscall path. So an i686 build is a second kernel that shares the portable C code.

## What was measured (2026-11-23)

- 94 kernel C files, 5 assembly files (`kernel/src/*.S`).
- 11 files contain x86_64-specific code (`%r*` registers, `iretq`, `cr3`, MSRs).
- 1 file depends on 64-bit ELF (`Elf64_`).
- Build flags are fixed to `-m64 -march=x86-64 -mcmodel=kernel` (kernel) and
  `-m64 -march=x86-64 -mcmodel=small` (user programs).
- Limine ships `BOOTIA32.EFI` (32-bit UEFI) and `limine-bios.sys`, so the boot loader is
  already available. Whether Limine loads an ELF32 kernel with the limine protocol on our
  version still needs to be checked (milestone I0).

## Milestones

| Milestone | Goal | Gate (must be seen) |
| --- | --- | --- |
| **I0** | `ARCH=i686` build: `-m32`, an ELF32 kernel linked at a low address, Limine boots it. The kernel prints a banner over serial and halts. | `i686-boot-test` prints `HELIX OS i686` and `Boot successful.` under QEMU SeaBIOS (`qemu-system-i386`) |
| **I1** | Architecture split: move the x86_64 pieces (GDT/IDT, trap entry, context switch, paging) behind `kernel/arch/x86_64/` and `kernel/arch/i686/`. The x86_64 build must not change. | `make test` still passes unchanged on x86_64 |
| **I2** | i686 paging and memory: 32-bit page tables (PAE first, for NX and >4 GiB), PMM and heap on i686. | i686 memory self-test prints PASS |
| **I3** | i686 core: console, keyboard, PIT timer, scheduler and context switch, serial shell (`helixsh`). | Serial shell runs `sysinfo` and `ls` under QEMU |
| **I4** | ELF32 loader and ring-3 programs with `int 0x80` syscalls using the 32-bit ABI. | A 32-bit user program prints via a syscall and exits |
| **I5** | Storage and filesystems (ext4 read, FAT32) and PCI on i686. | `disk` and `fat` checks pass on i686 |
| **I6** | Decide, per subsystem, what is in or out for i686: networking, desktop, TLS, Mac and DoneJS compatibility, Linux compat. | Written list in this file |

## Out of scope for the first pass

- The Mac/Darwin compatibility layer and DoneJS (both 64-bit today).
- The 64-bit TLS suites (`x25519`, `chacha20`, `x509`) unless they build cleanly on i686.
- Real hardware. Every i686 claim starts as a QEMU result.

## Open decisions

- PAE or non-PAE paging for i686. PAE is needed for NX and memory above 4 GiB, and is the
  default assumed here.
- Whether the i686 build keeps the same syscall numbers as x86_64.
- Whether i686 gets its own `version.h` identity string (`i686` suffix).

## Honesty rule for this port

The i686 kernel is not called working until each milestone above has been built and its
gate seen in a run. Until I0 passes, the answer to "does Helix support 32-bit?" is no.
